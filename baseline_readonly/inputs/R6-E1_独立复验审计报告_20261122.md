## 4. 新发现：R6-08 数值证据联合可行性错误（P0）

证据位置：`implementations/provisional_s2_r608/src/ap41_r608.py` 与 `implementations/provisional_s2_r608/oracle/reference.py`。二者均对 `Q_i^Y(B)` 的**上界**大于 `q_i` 的上界直接返回错误。原设计第 `QY_EXCEEDS_Q_INVALID` 个测试同样固化了该判断。

反例：`q0=q1=[1/2,1/2]`，`Q0_Y=[0,3/4]`，其他参数合法。因真实联合质量可以取 `Q0_Y=1/4`，原上界 3/4 虽粗，却是有效外包围；与 `0≤Q0_Y≤q0=1/2` 相交后仍有 `[0,1/2]` 可行区间。**因此不能仅因 3/4>1/2 判证据矛盾**。真正的不可行例子是 `lower(Q0_Y)>upper(q0)`，或在全部联合约束下可行域为空。

独立实际运行：现有 subject 返回 `INVALID_EVIDENCE`；oracle 使用同一过强规则，因此历史 18/18 PASS 无法检出双方一致错误。

其他输入边界探针：当 `Q0_Y`、`q0`、`Pe` 或 `Gamma` 的部分输入包围含负下界时，当前代码有时继续输出 `DECIDED`。这不必然意味着数学性质判定错，因为保守外包围可超出自然界，但说明**输入格式的域检查、已知自然界的裁剪、真实不一致性与认证来源核验必须先统一成明确合同**。不能在某处把宽松区间视为证据无效、另一处却不检查。

整改要求：主理论助手冻结 `q_i`、`Q_i^Y(B)`、`Pe`、`Gamma` 的证据语义与合法性；实现对已认证区间与物理约束取交集，空集才按矛盾处理；区分“模型输入非法”与“证据不可行”与“数值不足导致未决”；独立 oracle 必须走不同联合可行性方法（例如线性约束可行性），加入合法宽松包围、空集证据、多事件类别求和约束和同一事件质量来源的负测。

## 5. 新发现：最终验收器对内容篡改不敏感（P0）

证据位置：`tests/final_verify_r6.py`。它只检查少数文件的计数/标签和 `scope_manifest_v2.json` 中的预设总体状态，大量 `counts` 与阶段状态为常量字符串，不重新读取局部语义测试的原始日志、失败变异和真实模型输出。

独立负测：仅将 `chapter6/raw_population_5000.csv` 第一条记录 `file_sha256` 替换成 64 个 `0`，保留行数和工件数，运行 `python -B tests/final_verify_r6.py`。**实得退出码 0、错误列表空、未检出篡改**。该负测仅针对 `final_verify_r6.py` 的验收能力，不否认 ZIP 附带的独立哈希清单本身可以检出相应文件更改。负测后已经恢复隔离副本，不改动原 ZIP。

整改要求：从模型及证据来源重新计算结论，不信任硬编码聚合计数；本机外部路径不可用于便携包直接复验的要返回 `MISSING_DEPENDENCY`；必须有篡改单项证据导致整体 FAIL 的端到端负测。

## 6. 新发现：原始文件级可移植复现失败（P0）

证据位置：`chapter6/build_population.py`，其 `SRC` 写死一个用户本机 `Downloads` 目录。独立环境执行时，读取 `split_plan.csv` 产生 `FileNotFoundError`，退出码 1。ZIP 内有来源清单、文件哈希和部分加工特征，但没有源目录中的 5000 个原始 JSON；因此本次审计只能验证清单的字段与内部一致性，无法从原始文件逐个复算全部数值。

整改要求：以输入根路径参数或只读数据清单的声明式 URI 代替绝对路径；原始 JSON 若因许可/体积不能入包，应提供授权访问或逐项独立原始哈希验证步骤，并如实声明外部原始数据依赖。没有原文件时，仅能给出 `SOURCE_MANIFEST_AUDITED`，不能给 `FULL_RAW_REPRODUCIBLE`。

## 7. 对 P0-A/P0-B/M11 的再评估

V1.5 受限引擎 `implementations/common/propagation.py` 通过 `M^-` 前后使能分类选择 `persistent/reset`，随后调用 `_kernel(lifecycle,boundary)` 的**专用解析区域公式**，并将类别质量、时间桶和终止账本输出。该链路较 V1.4 确实增加了从实际网络时钟类别到数值计算选择的因果联系，旧错误与源码变异均有真实日志。

但它的输入域要求恰好 `x,y,z` 三个特定均匀计时器、专用即时根/后继形状，概率传播不是通用的时钟事件树或任意 LSTPN 联合分布传播引擎。**认可为受限闭式子类的真实语义回归，不得向上归纳为一般模型实施就绪。** 下一轮必须再通过同一受限子类的分布/结构微扰核验，确认支持边界不会错误接受超出子类的合法网络并输出固定公式。

## 8. 与 v3.0 全量、经典基线和敏感性规划对照

- v3 的 L-01—L-10 及 P-01—P-08 学术/工具基线尚没有完整登记、文献原始语义复核、可运行版本哈希、同题适配器或逐对象结果。
- 第六轮正式逻辑评价不能把 54 个四轴格当成更大 8 轴生成器声明域的充分替代；143360 个只是形式候选格，需先给出预冻结合法性判据，再实际枚举全部候选及排除原因。
- v3 的 `54×10×3=1620`、`L/H` 规格扩展和 `21×3×3×3=567` 概率矩阵，均未形成对应冻结运行清单，不能报告任何敏感性结论。1620 本身也不能替代大八轴主域。
- PyScrew 5000 来源审计≠原始 5000 全数据建模≠48 比较证书。物理变化类别和 Petri 网故障变迁事件是不同层级的标签，必须先验证可测对齐和故障历史映射，不得把原始故障标签自动当 LSTPN 发射故障。
- 必须分别报告完整原始数据的经验效果、可建模工况的模型条件风险认证、旧 32 工况同域对照；不将 AUROC/Brier/NLL 直接用于证明数学证书。

## 9. 必要整改优先级

**P0 强制先行**：
1. `R6-08-QY-CONSISTENCY`：联合质量区间的可行收紧和错误域定义；subject/oracle 同步错误必须由第三路径独立对抗发现。
2. `FINAL-VERIFY-TAMPER`：终验不再只复核数量；实际重算、哈希、模型/日志绑定、负测。
3. `RAW-PORTABILITY`：5000 JSON 来源可独立访问与校验，去除本机绝对路径；不能交付时严格限定证明级别。
4. `GENERATOR-SCOPE-143360`：先解决 54 与 143360 的实验总体验收口径，再冻结全量矩阵。
5. `FRESH-LOGIC-ENGINE`：独立新构建合法模型诊断引擎和四方法，而非继续搜寻已失源的旧 Linux 程序。
6. `FULL-PYS-PIPELINE`：对全部来源和可建模组的完整实验；故障事件与外部观测约束先行验收。
7. `BASELINES-SENSITIVITY`：落实 v3.0 正式同题性审查、外部经典基线、全量敏感性数据表。
8. `INDEPENDENT-SIGNOFF`：真实独立审查、完整证据负测及声明范围联合终验。

**P1 随后完成**：TINA 31 旧证据缺失的可用查询重建、1413/1421 历史数据分母对账、九项 TeX 映射语义澄清、R6-01 的端点与即时优先、其余 R6-02—R6-13 的全模块回归。对影响数学正确性或全量结论的 P1 在最终联合验收前不得留空。

## 10. 最终裁定与声明限制

本轮可归档完整 ZIP 哈希及局部真实 PASS，不能把 `results/final_verification_r6.json` 中的局部数字作为学位论文主实验重跑结果；不能基于 54 个构造模型或 5000 行来源清单报告逻辑加速比、严格概率风险证书率或多因素敏感性结论。`S-1=BLOCKED`、`S1=PROVISIONAL`、`S2–S5=NOT_EXECUTED`、`G7=NOT_CLOSED`，结论不随本审计所做的局部复跑而改变。
