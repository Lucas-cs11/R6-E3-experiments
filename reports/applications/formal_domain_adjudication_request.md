## 1. 关键事实裁决点

**F1：故障位置语义是饱和上界，不是精确需求。** 冻结规则 R6 为 `1 ≤ fault ≤ machine_counts`；但生成器实际约束为 `fault ≤ min(machine, j×ops)`（`rng.sample(used_machines, min(fault, |used|))`，仅 used_machines 建库所）。3,840 个合法行满足 `j×ops < fault ≤ machine`，其网络实际饱和在 j×ops 台故障机：请求 4–8 → 实际 2–6 台故障机、4–12 个故障变迁，四种模式（(4,2,2,4) 1280；(8,2,2,4) 512；(8,4,4,8) 1024；(8,6,6,12) 1024）。

**F2：3,840 个饱和格全部 TINA BOUNDED**（见 §3 计数），不构成动态有效性问题。

**F3：seed 全域恒为 0。** 宇宙内没有种子轴；`n_seeds: 15`、`param_slice: 3` 是旧协议 `fullscale_protocol_corrected.yaml` 的声明（每轴前 3 值 × 15 种子），README 记载 36,450 实例。其逐行来源与“历史 52 主模型为何只覆盖 36/54 格”现有材料无法核实，维持 `PROVENANCE_UNRESOLVED`：36,450 = 15 × 2,430，2,430 无法由修正协议各轴取值数整分解出（各轴 3 值时全积 6,561/种子），故 36,450 不是修正协议八轴直积；历史 36 个生成模型原始字节缺失，重建身份只能标 `RECONSTRUCTED`。

**F4：规范内容重复仅来自两个参数轴。** 语义网络内容（规范化库所/初始标识/变迁含标签与故障可调标志及区间/弧/完成标识）：
- machine_counts：3,328 对无实效（超出工序数的机器不进入网络）；
- adjustable_ratios：1,344 对无实效（小总数下取整相同且采样集相同）；
- 其余六轴 0 对；seed 无可比对。
